## 4. Семь вопросов (памятка) — ответы для защиты

1. **Какую полезную задачу решает агент?** — Исследовательский агент: по вопросу собирает факты из веба (Yandex/DDGS/Tavily по приоритету `SEARCH_PRIMARY`), читает страницы, выдаёт структурированный ответ с источниками и уверенностью.
2. **Где агент сам выбирает следующее действие?** — В цикле `ResearchAgent.run`: LLM решает, вызвать инструмент или завершить (tool_calls vs финальный JSON). Остановка: `MAX_STEPS`, бюджет, circuit breaker.
3. **Когда и почему выбирается каждая модель?** — Исследователь = `RESEARCHER_MODEL` (qwen3.7-flash) через RouterAI (primary) / OpenRouter (fallback); судья = `JUDGE_MODEL` (gemini-3.5-flash-lite) — отдельный вендор, чтобы не оценивать ответы своей экосистемы.
4. **Какой инструмент через function calling?** — `search_web` (поиск с fallback-цепочкой), `fetch_url` (с SSRF-защитой), `save_note` (фиксация фактов).
5. **Когда агент обращается к «памяти» и что при пустом результате?** — «Память» здесь — контекст шагов: заметки `save_note` и результаты инструментов накапливаются в сообщениях цикла; при недостатке данных агент повторяет поиск (формирует новый запрос), при исчерпании шагов — отдаёт частичный ответ со `stop_reason`. (Векторная память по памятке — требование финальной *проектной* работы, в модульном ДЗ не требуется.)
6. **Где ветвление, повтор шага, условие остановки?** — `agent.py`: цикл с проверкой tool_calls; `MAX_STEPS` и `MAX_COST_USD` — остановка; `stop_reason` (`completed` / `max_steps_exceeded` / `budget_exceeded` / `invalid_answer` / `error`).
7. **Как доказать, что система работает правильно и стабильно?** — Юнит-тесты (60), LLM-as-judge (score/verdict), golden set с pass@1, evals со стабильностью по прогонам (`--runs 3`), трейсы в Phoenix, guardrails (injection/валидация/circuit breaker) в `dz_report.md`.
